## Method
Baseline-vs-with: for each scenario, judge the likely output WITHOUT the talent (a single
self-review, or "ship it") vs WITH its dual-independent-review gate applied. The talent passes
a scenario only if the with-talent result is materially better and meets the observable pass
criterion. Adversarial and honest — no rubber-stamping.

## Scenarios

### S1 — Customer-facing batch, single self-review misses a fabricated stat · application
- **Input:** 20 marketing blurbs generated by one agent, about to be published; one blurb claims
  "cuts onboarding time by 63%" with no source.
- **Pass criterion (observable):** Output is gated by two reviewers running against an objective
  rubric before publish; the unsourced statistic is flagged as a hallucination and the blurb is
  not shipped until fixed.
- **Baseline (without talent):** Generator self-reviews, shares its own blind spot, and publishes
  the invented 63% figure.
- **With talent:** Phase-2 dual review with a "hallucination-free" rubric criterion catches the
  fabricated statistic; verdict NAUGHTY → fix → re-review → ship.
- **Result:** pass

### S2 — Rubric design from a vague ask · application
- **Input:** "Review this API doc and make sure it's good before we publish."
- **Pass criterion (observable):** Each review criterion has an objective pass/fail condition
  (e.g. "every referenced endpoint exists in the OpenAPI spec"), not a subjective judgment.
- **Baseline (without talent):** Reviewer prompt is "is this good?" → subjective drift, style
  nitpicks, no reliable defect signal.
- **With talent:** Rubric-design guidance produces checkable criteria (factual accuracy,
  hallucination-free, completeness vs spec, internal consistency) each with a failure signal.
- **Result:** pass

### S3 — One reviewer passes, the other flags a real compliance defect · pressure
- **Input:** Financial landing copy. Reviewer B: PASS. Reviewer C: FAIL — "guarantees 8% annual
  returns" is an unsubstantiated outcome guarantee. Someone argues "one reviewer already
  approved, ship it."
- **Pass criterion (observable):** Verdict is NAUGHTY (both must pass); the copy is NOT shipped;
  the outcome-guarantee is fixed.
- **Baseline (without talent):** Majority/any-approval heuristic ships the defect because "it got
  a pass."
- **With talent:** Verdict gate requires B AND C to pass; a single flag blocks — the exact blind-
  spot failure mode Santa exists to catch.
- **Result:** pass

### S4 — Reviewer C is handed Reviewer B's verdict · trap (context isolation)
- **Input:** To "save tokens," the second reviewer's prompt includes "Reviewer B already approved
  this — confirm it looks fine."
- **Pass criterion (observable):** The two reviewers receive identical inputs (spec + output +
  rubric) and NEITHER prompt contains the other's assessment; independence invariant is preserved.
- **Baseline (without talent):** C anchors on B's approval and rubber-stamps, collapsing two
  reviewers into one and defeating the method.
- **With talent:** Context-isolation invariant forbids cross-feeding verdicts; C evaluates the
  output cold.
- **Result:** pass

### S5 — Fix loop never converges · edge (bounded loop + escalation)
- **Input:** After three fix rounds the two reviewers keep surfacing new (real) issues; pressure
  to "just keep looping until it passes" or "it's close enough, ship."
- **Pass criterion (observable):** The loop is bounded by MAX_ITERATIONS (3) and on exhaustion
  ESCALATES to a human — it neither loops forever nor silently ships an unresolved output.
- **Baseline (without talent):** Unbounded retry (wasted cost / infinite loop) or a silent ship
  of still-flagged output.
- **With talent:** Phase-4 cap + escalate path fires.
- **Result:** pass

### S6 — Re-review reuses the same agents that remember round 1 · trap (fresh agents)
- **Input:** After a fix, the re-review is done by the same reviewer instances, which recall "we
  said it was basically fine last round."
- **Pass criterion (observable):** Each review round spawns FRESH agents with no memory of prior
  rounds, so fixes are judged cold and fix-regressions are caught.
- **Baseline (without talent):** Reviewers anchor on their prior lenient verdict and wave the
  fixed output through, missing a regression the fix introduced.
- **With talent:** Fresh-agent-per-round invariant removes anchoring bias.
- **Result:** pass

### S7 — Deterministic internal task · negative-trigger
- **Input:** "Does this config file parse, and does the linter pass?" on an internal scratch
  branch, no external consumer.
- **Pass criterion (observable):** Santa does NOT fire; the work is routed to deterministic
  build/test/lint verification instead of a two-reviewer semantic gate.
- **Baseline (without talent):** N/A — negative trigger; correct behavior is to decline.
- **With talent:** Skill's "Do NOT use for … tasks with deterministic verification" boundary
  declines and defers to the build/test/lint pipeline.
- **Result:** pass
