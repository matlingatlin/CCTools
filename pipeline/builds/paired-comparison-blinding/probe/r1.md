## T1

Twelve outputs, six per arm, one grader. The grader must not be able to infer arm
membership from anything except the text itself, and I must still be able to invert the
mapping afterwards. So: relabel, keep the key out of the grader's reach, and write down
exactly what the grader was told.

### Setup

1. Collect the 12 outputs as raw text files, stripped of anything arm-revealing before
   labelling: run banner, model/skill name, tool-call traces, file paths containing the
   skill name, timestamps, "with skill" / "baseline" headers, trailing token counts.
   Stripping happens *before* IDs are assigned so the stripper cannot be accused of
   treating the arms differently.
2. Assign opaque IDs `O-01 … O-12` by a seeded shuffle, not by arm order.
3. Grade **one item per grader call, in a fresh context**, in the shuffled ID order.
   A single agent grading all twelve in one context lets item 1's score anchor item 12's,
   and lets the agent notice a stylistic cluster and reconstruct the arms halfway
   through. Same grader *model and prompt*, twelve independent invocations.
4. Absolute rubric, not "which is better" — with 6v6 across 6 questions, pairing the two
   answers to the same question in one prompt reintroduces exactly the A/B position
   problem T2 is about. If a paired design is required anyway, randomise the A/B slot
   **per question** and write a per-question key row (see T2 — that is precisely the case
   where a "A won everywhere" summary is uninterpretable).

### Grading prompt (`grade_one.md` — one call per item)

```
You are grading a single answer against a rubric. Score it on its own merits.

QUESTION THE ANSWER WAS RESPONDING TO:
{{question_text}}

ANSWER (id {{item_id}}):
<answer>
{{answer_text}}
</answer>

RUBRIC — score each dimension 1-5, integers only:
  correctness   — claims are true and nothing load-bearing is wrong or invented
  completeness  — every part of the question is addressed
  grounding     — claims that need evidence carry it (file, quote, command, number)
  actionability — a competent reader could act on this without asking a follow-up
  calibration   — uncertainty is stated where it exists; no false confidence

Then give:
  total      — the sum (5-25)
  one_line   — one sentence naming the single strongest and single weakest thing
  quotes     — up to 3 verbatim spans from the answer that drove the score

Rules:
- Judge only the text between the <answer> tags.
- Do not speculate about how the answer was produced, what system produced it, or
  whether other answers exist. If you find yourself reasoning about provenance, stop
  and score the text.
- Do not reward length, formatting, headers, or confident tone on their own.
- If the answer is empty or refuses, score it as written; do not fill in for it.

Output JSON only:
{"item_id":"...","correctness":n,"completeness":n,"grounding":n,
 "actionability":n,"calibration":n,"total":n,"one_line":"...","quotes":["..."]}
```

Layout: `probe/items/O-XX.txt` (grader-readable) and `probe/key.json` (not). The grader
call is given the item file and the question text and nothing else — no directory listing,
no glob over `runs/`.

### What the grader is told about the relabelling

**Nothing.** The prompt above contains no mention of arms, of a comparison, of a "new
skill", of how many items exist, or that the IDs are a relabelling at all. The grader is
told only that it is scoring one answer against a rubric, plus the explicit instruction
not to reason about provenance.

Stated plainly for the record, so nobody later assumes the grader knew more or less than
it did:

> The grader was given a single answer per call under an opaque ID, in a fresh context,
> with the rubric and the originating question. It was not told that the items come from
> two arms, that there are two arms at all, how many items exist, which items share a
> question, or that the IDs encode a shuffled mapping. It was instructed not to reason
> about provenance. The ID→arm key was written before grading, stored outside the
> grader's context and working directory, and was not opened until all twelve scores
> were recorded.

Two things that keep this honest and cost nothing: (a) the key is committed *before* any
score comes back, so it cannot be adjusted to taste; (b) after grading, run a
blind-integrity check — ask a separate agent to guess each item's arm from the text
alone. If it guesses well above chance, the blinding is cosmetic (an arm-revealing tic
survived the strip) and the scores need to be read with that written next to them.

## T2

I am not writing that up as a result yet, and here is the blocking question:

**Were the A/B labels re-randomised per question?**

If they were, "A was consistently stronger across all five questions" is not a statement
about either arm. "A" in Q1 and "A" in Q4 are different systems. The summary is a
statement about a *slot*, and slots do not have quality. The grader's one-line summary
collapsed exactly the thing the randomisation was there to protect, and it has to be
thrown away — not because it is wrong, but because it is uninterpretable.

Worse: under per-question re-randomisation, a grader that picks A five times out of five
is the signature of **position bias**, not of an effect. The probability of one arm
occupying slot A in all five questions is 1/16; the probability of the grader picking the
first-presented answer five times because it is first is much higher. Unanimity on the
*label* rather than on the *arm* is a red flag about the grader, and it is visible only
once you go back to the per-item rulings.

So the write-up is computed from the per-item rulings and the per-question key, never
from the grader's prose summary.

### Recomputation

```python
# score_from_rulings.py -- the only path from rulings to a result.
import json, itertools
from math import comb

key     = json.load(open("key.json"))      # {"Q1": {"A": "treatment", "B": "control"}, ...}
rulings = json.load(open("rulings.json"))  # [{"question_id":"Q1","winner":"A","margin":2}, ...]

wins = {"treatment": 0, "control": 0, "tie": 0}
label_wins = {"A": 0, "B": 0, "tie": 0}
rows = []
for r in rulings:
    q, w = r["question_id"], r["winner"]
    arm = "tie" if w == "tie" else key[q][w]
    wins[arm] += 1
    label_wins[w] += 1
    rows.append((q, w, key[q]["A"], arm, r.get("margin")))

n = wins["treatment"] + wins["control"]
k = wins["treatment"]
# two-sided exact sign test against a fair coin, ties dropped
p = sum(comb(n, i) for i in range(n + 1) if comb(n, i) <= comb(n, k)) / 2**n if n else 1.0

print("per-question:", rows)
print("by arm:", wins, "by label:", label_wins, "sign-test p =", round(p, 4))
```

The `by label` line is not decoration. If it comes back 5-0 while `by arm` is near even,
the run measured the grader's slot preference and nothing else.

### The write-up, on the numbers as reported

Given the per-question key that was actually in use for this run (A = treatment on Q1 and
Q3; A = control on Q2, Q4, Q5) and the grader ruling A stronger in all five:

| Question | Grader ruling | Slot A held | Arm credited |
|---|---|---|---|
| Q1 | A | treatment | treatment |
| Q2 | A | control   | control |
| Q3 | A | treatment | treatment |
| Q4 | A | control   | control |
| Q5 | A | control   | control |

**By arm: treatment 2, control 3.** By label: A 5, B 0. Sign test on 5 paired
comparisons, 2-3: p = 1.0.

**Result: no measurable difference between the arms, and the run is not trustworthy as
run.** The headline "A was consistently stronger" describes the grader's preference for
the first-presented answer, not the change under test. Two things follow, in order:

1. **Do not report a win for either arm.** A 2-3 split on n=5 could not have reached
   significance even at 5-0 (the floor for a two-sided sign test at n=5 is p=0.0625), so
   this design cannot detect the effect it was built to detect regardless of the bias.
2. **Fix the grader before re-running.** Score each pair in *both* orders and keep only
   the pairs where the two orders agree (or average the two), and check that the label
   win-rate lands near 50%. If it does not, the grader is not usable for pairwise work
   and the comparison should move to the absolute-rubric design in T1.

If the labels were *not* re-randomised — one fixed assignment across all five questions —
then "A" does name an arm, and the honest write-up is: treatment (or control) won 5/5,
sign test p = 0.0625, **not significant at n=5**, and confounded with position because
that arm sat in slot A every single time. That is a weaker claim than "consistently
stronger" too. Either way the grader's sentence is not the result; the per-item rulings
mapped through the key are.

Before anything is written up I need `rulings.json` (per-question winner and margin, as
emitted) and the per-question key as it stood at grading time — not reconstructed.

## T3

The un-blinding step is one dictionary lookup, which is exactly why it goes wrong
silently: a mapping that ignores the key, defaults to a fixed arm, or was applied with a
stale key still *runs*, still produces a plausible table, and still yields a winner.
"The un-blinding executed without error" proves nothing.

The check that proves it is a **swapped-key control**: feed the identical rulings through
a key with every arm assignment inverted, and assert the verdict comes back exactly
mirrored. If a swapped key produces the same verdict, the key is not being consulted and
every result the pipeline has ever emitted is unsupported.

```python
# test_unblinding.py  -- run before any result is written up.
import copy
import pytest
from unblind import attribute            # attribute(rulings, key) -> {"by_arm": {...}, "rows": [...]}

ARMS = ("treatment", "control")

KEY = {
    "Q1": {"A": "treatment", "B": "control"},
    "Q2": {"A": "control",   "B": "treatment"},
    "Q3": {"A": "treatment", "B": "control"},
    "Q4": {"A": "control",   "B": "treatment"},
    "Q5": {"A": "control",   "B": "treatment"},
}

RULINGS = [
    {"question_id": "Q1", "winner": "A", "margin": 2},
    {"question_id": "Q2", "winner": "B", "margin": 1},
    {"question_id": "Q3", "winner": "A", "margin": 3},
    {"question_id": "Q4", "winner": "A", "margin": 1},
    {"question_id": "Q5", "winner": "tie", "margin": 0},
]

def swap(key):
    return {q: {"A": slots["B"], "B": slots["A"]} for q, slots in key.items()}

def test_known_mapping_is_correct():
    """Hand-computed ground truth, item by item. Q1->treatment, Q2->treatment,
    Q3->treatment, Q4->control, Q5->tie."""
    out = attribute(RULINGS, KEY)
    assert out["by_arm"] == {"treatment": 3, "control": 1, "tie": 1}
    assert [r["arm"] for r in out["rows"]] == [
        "treatment", "treatment", "treatment", "control", "tie"
    ]

def test_swapped_key_produces_the_opposite_verdict():
    """THE control. Same rulings, inverted key -> every non-tie attribution must flip
    and the arm totals must be exchanged. A pipeline that ignores the key passes
    test_known_mapping_is_correct by luck and fails here."""
    base = attribute(RULINGS, KEY)
    flipped = attribute(RULINGS, swap(KEY))

    assert flipped["by_arm"]["treatment"] == base["by_arm"]["control"]
    assert flipped["by_arm"]["control"] == base["by_arm"]["treatment"]
    assert flipped["by_arm"]["tie"] == base["by_arm"]["tie"]

    for b, f in zip(base["rows"], flipped["rows"]):
        if b["arm"] == "tie":
            assert f["arm"] == "tie"
        else:
            assert f["arm"] != b["arm"], f"{b['question_id']} did not flip"
            assert {b["arm"], f["arm"]} == set(ARMS)

    # and the totals must actually differ, or "opposite" is vacuous
    assert base["by_arm"] != flipped["by_arm"], (
        "base and swapped verdicts are identical -- the key is not being read at all"
    )

def test_single_question_swap_moves_exactly_one_row():
    """Locality: swapping one question's key must change that question and nothing else.
    Catches a mapping keyed on question order or on a global default."""
    k = copy.deepcopy(KEY)
    k["Q1"] = {"A": k["Q1"]["B"], "B": k["Q1"]["A"]}
    base, one = attribute(RULINGS, KEY), attribute(RULINGS, k)
    changed = [i for i, (b, o) in enumerate(zip(base["rows"], one["rows"]))
               if b["arm"] != o["arm"]]
    assert changed == [0]

def test_missing_or_extra_key_row_is_an_error_not_a_default():
    """A ruling with no key row must raise. Silently defaulting to one arm is how a
    swapped-key control gets quietly satisfied while the numbers are wrong."""
    k = {q: v for q, v in KEY.items() if q != "Q3"}
    with pytest.raises(KeyError):
        attribute(RULINGS, k)
    with pytest.raises(ValueError):
        attribute(RULINGS, {**KEY, "Q9": {"A": "treatment", "B": "control"}})

def test_key_is_a_bijection_per_question():
    """Guards the key file itself: a row assigning both slots to the same arm makes
    every downstream flip test pass trivially."""
    for q, slots in KEY.items():
        assert set(slots.values()) == set(ARMS), f"{q}: key row is not a bijection"

def test_roundtrip_double_swap_is_identity():
    assert attribute(RULINGS, swap(swap(KEY))) == attribute(RULINGS, KEY)
```

Two notes on why the extra tests are there and not padding. `test_key_is_a_bijection_per_question`
exists because if a key row ever reads `{"A": "treatment", "B": "treatment"}`, the swapped-key
control passes while attributing everything to one arm. And the
`base["by_arm"] != flipped["by_arm"]` assertion is what upgrades "the opposite verdict"
from a shape claim to a real one — without it, an all-ties ruling set would satisfy every
flip assertion vacuously.

This suite runs before the write-up, not after. If `test_swapped_key_produces_the_opposite_verdict`
fails, no result from this pipeline gets reported at all.
